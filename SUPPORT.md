# Support

## Before opening an issue

1. Check the README and existing issues.
2. Confirm the problem still occurs on the latest release.
3. Make a workspace backup before testing destructive or migration steps.

Use the bug template for reproducible product problems and the feature template for a focused proposal. Include the 900Notes version, operating system, what you expected, what happened, and the smallest reliable reproduction. Remove note content, usernames, file paths, tokens, and other private data from logs and screenshots.

Community support is best effort. There is no guaranteed response time or service-level agreement.

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md).
