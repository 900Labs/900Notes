# Governance

900Notes uses maintainer-led governance.

Maintainers set release scope, review contributions, manage repository access, and make final decisions when consensus is not reached. Decisions should favor user data integrity, offline operation, accessibility, modest hardware requirements, and a codebase that volunteers can understand.

Substantial changes should begin with an issue that describes the user problem, scope, tradeoffs, and migration impact. Small fixes can go directly to a pull request. A maintainer other than the author should review release-critical changes when practical.

New maintainers are invited based on sustained, constructive contributions and sound judgment. Access can be reduced after prolonged inactivity or conduct and security concerns. The current maintainer list is the set of people with write access shown by GitHub.

Project policy changes are made through pull requests so the discussion and decision remain visible.
