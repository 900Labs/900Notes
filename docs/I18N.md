# Internationalization (i18n) Guide

900Notes supports 10 languages out of the box. The i18n system is designed to be simple, offline, and dependency-free.

## Supported Languages

| Code | Language | RTL | Native Name |
|------|----------|-----|-------------|
| `en` | English | No | English |
| `fr` | French | No | Français |
| `es` | Spanish | No | Español |
| `sw` | Swahili | No | Kiswahili |
| `hi` | Hindi | No | हिन्दी |
| `ar` | Arabic | Yes | العربية |
| `pt` | Portuguese | No | Português |
| `bn` | Bengali | No | বাংলা |
| `ur` | Urdu | Yes | اردو |
| `am` | Amharic | No | አማርኛ |

## Architecture

```
src/i18n/index.ts
├── Locale type and locale list
├── locale store (writable<Locale>)
├── t store (derived from locale)
├── setLocale() function
└── translations object (Record<Locale, Record<string, string>>)
```

### How it works

1. `locale` is a Svelte writable store holding the current language code
2. `t` is a derived store that produces a function `(key, params?) => string`
3. When `locale` changes, `t` automatically recomputes
4. Components use `{$t('key')}` to get translated strings
5. `setLocale()` updates the store and sets `document.documentElement.dir` and `lang`

## Usage in Components

```svelte
<script lang="ts">
  import { t } from '../i18n'
</script>

<p>{$t('sidebar.pages')}</p>
<p>{$t('search.results', { count: 5 })}</p>
```

### String interpolation

Translation values can contain `{paramName}` placeholders:

```typescript
'search.results': '{count} results'
```

```svelte
{$t('search.results', { count: results.length })}
```

## Adding a New Language

1. Add the locale to the `Locale` type and `locales` array in `src/i18n/index.ts`:

```typescript
export type Locale = 'en' | 'fr' | 'es' | 'sw' | 'hi' | 'ar' | 'pt' | 'bn' | 'ur' | 'am'

export const locales = [
  // ... existing locales
  { code: 'pt', name: 'Português', rtl: false },
]
```

2. Add a translation object with all keys:

```typescript
const translations: Record<Locale, Record<string, string>> = {
  // ... existing languages
  pt: {
    'app.title': '900Notes',
    'app.tagline': 'Seu Segundo Cérebro, Totalmente Seu',
    // ... copy all keys from 'en' and translate
  },
}
```

3. Add the language to the Settings modal in `src/components/settings/SettingsModal.svelte` (it reads from the `locales` array automatically).

4. Test with RTL if applicable: set `rtl: true` in the locale definition.

## Translation Key Conventions

Keys use dot notation with the pattern `section.key`:

| Prefix | Section |
|--------|---------|
| `app.*` | App-level strings (title, tagline) |
| `sidebar.*` | Sidebar labels |
| `editor.*` | Editor labels and placeholders |
| `search.*` | Search palette |
| `settings.*` | Settings modal |
| `trash.*` | Trash tab |
| `common.*` | Common buttons (cancel, save, etc.) |
| `slash.*` | Slash menu block names |
| `link.*` | Wiki link autocomplete |

## RTL Support

Arabic (`ar`) and Urdu (`ur`) are RTL languages. RTL is handled by:

1. `setLocale()` sets `document.documentElement.dir = 'rtl'` for RTL locales
2. TailwindCSS automatically mirrors logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`)
3. ProseMirror list padding and blockquote borders are mirrored via `[dir='rtl']` CSS selectors in `src/app.css`
4. The sidebar and backlinks panel swap sides naturally with flexbox + `dir="rtl"`

## Adding Translation Keys

When adding new UI text:

1. Add the key to the English (`en`) translations first
2. Copy the key to all other languages with translations
3. If you can't translate to a language, copy the English string as a placeholder - it will be translated later
4. Use the key in your component with `{$t('your.key')}`
